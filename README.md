# jAgent

A skill for agents, and a library behind it. Fourteen reviewed skills, workflows and interface resources, with the routing that tells an agent which one to open for the job.

```sh
npx skills add wuzzynizzy/jAgent
```

`SKILL.md` is the entry point. The website is the readable half of the same content.

Canonical URLs are https://wuzzynizzy.github.io/jAgent/ and https://jagent.pages.dev/. Nothing is published from a merge: `releases/jagent-pages-<version>.zip` is the upload archive, and the Pages workflow only publishes when it is run by hand.

## What is in it

- `SKILL.md`, the skill entry: when to use the library, twelve routes, and the rules that stop one resource overriding another.
- Fourteen resource pages. Each one covers what the tool does, the commands that run it, when it fits, where it stops, and the commit it describes.
- Recorded source trees for every resource, with each tracked path at the pinned commit linked to GitHub.
- Twelve task routes that map a job to a lead resource and a short sequence of steps.
- A typed knowledge graph of resources, guides and routes, with every edge also listed as text.
- Lexical search over 124 passages, running in the browser against a static index.
- Agent files: `llms.txt`, `AGENTS.md`, a versioned manifest, per-page chunks with stable source IDs, and checksums for the whole deployment.
- Guides: design contract, context protocol, retrieval status, provenance, versions and recovery.

## What it is not

No server, no vector database and no model in the loop. Search is lexical and local. The site publishes public resource material only; private notes, project handoffs and credentials are not part of it and never will be.

The retrieval page states this plainly, including what a future vector integration would require.

## Build

```sh
python3 -m venv .venv
.venv/bin/pip install -r build/requirements.txt
.venv/bin/python build/build.py
.venv/bin/python build/check.py
```

`build/build.py` writes `public/` from `build/content` and `build/inputs`. Nothing else is read, so a clone can reproduce the site.

`build/check.py` verifies internal links and anchors, markdown twins, data cross references, chunk anchors, checksums, page metadata, the Cloudflare Pages limits, an explicit file allowlist and the privacy scan.

## Browser checks

```sh
npm install                      # puppeteer-core and a prebuilt Chromium
node build/browser_check.mjs --shots /tmp/jagent-shots
```

The script uses `puppeteer-core` with `@sparticuz/chromium`, so no separate browser download is needed. On a machine with its own Chrome, pass its path with `CHROME_PATH=/path/to/chrome`.

It serves `public/` on a local port and checks what a static scan cannot: Google Sans actually loading, console and request errors, horizontal overflow at 320, 390, 768, 1024 and 1440 pixels, the full metadata set and JSON-LD on every page type, theme switching with persistence and measured contrast in light mode, skip link and focus, category filters, search including the no-results and index-failure states, the recorded tree at 5,782 paths, graph selection and filtering, the copy control, reduced motion, and that Markdown and JSON are served as themselves.

## Package

```sh
.venv/bin/python build/package.py
```

That writes two archives into `releases/`:

- `jagent-pages-<version>.zip`: only the deployable site, with `index.html` at the archive root.
- `jagent-source-<version>.zip`: this repository without build output, dependencies or release archives.

A `SHA256SUMS.txt` file sits beside them.

## Deploy

## Layout

```
SKILL.md         skill entry: routes, rules, when to use
references/      six guides, plus resources/<id>.md write-ups, tasks.md
config/          site copy, resources, tasks, graph, seo, nav, theme
sources/         verified upstream registry and recorded trees
assets/          CSS, JS, fonts, Lucide icon paths, brand, social cards
build/           build, check, package and browser-test scripts
tools/           generators for icons, brand assets and the font subset
public/          generated site (not edited by hand)
releases/        packaged archives
```

## Theme, icons and brand

Dark and light are both first-class, with `Auto` following the operating system. Both palettes and their measured contrast ratios live in `config/theme.json`, and `assets/theme.css` is generated from it. Interface icons come from Lucide, extracted into `assets/icons.json` with the ISC notice beside it. Brand assets, favicons and the twenty-nine social cards are generated by `tools/make_brand.mjs` from the same type and palette.

## SEO

Every page ships title, description, canonical, robots directives, `og:*` including an absolute `og:image`, `twitter:card`, `article:*` where relevant, a web manifest, favicons, and JSON-LD (`WebSite` with `SearchAction`, `TechArticle`, `SoftwareSourceCode`, `CollectionPage`, `ItemList`, `BreadcrumbList`). `sitemap.xml` carries `lastmod`, `changefreq` and `priority`; `robots.txt` names the sitemap and allows the main agent crawlers.
